3. PHASE 2: PILOT JSX CONVERSION & ROOT CAUSE INVESTIGATION
================================================================================
- Action: Created a parallel pilot route at /about-us-v2 (app/about-us-v2/page.tsx)
  to test converting content.html into clean React JSX components.
- User Review: "nopes they are not identical ui wise" -> User reverted changes.
- Root Causes Identified:
  1. Missing Parent Classes: Avada CSS for Header and Footer relies on wrapper
     classes (.wp-theme-Avada, .fusion-body, .avada-responsive). When a plain
     JSX component rendered <main>, those parent classes were absent, causing
     the header to lose transparency and the footer to lose its column grid.
  2. Redesigning vs Preserving: The pilot attempted to replace Avada's layout
     with custom CSS modules (.hero { display: flex }). Avada uses specific grid
     math (rows with width: 104% !important; margin-left: -2%, columns with
     percentage widths like 3.84% margins). Guessing CSS caused alignment shifts.
  3. Header Document Flow: The header is position: absolute; top: 0; width: 100%.
     It requires the top hero section to have --awb-padding-top: 320px so it floats
     transparently over the image rather than pushing it down or covering text.

8. DEEP DIVE: WHY HEADER & FOOTER LOST CSS & THE 1-TO-1 SOLUTION
================================================================================
- User's Question:
  "why whenever i try to make it in pure next js header looses its css and footer too,
   and why cant we just replace the tags in html with next js tags?"
- The Breakthrough Answer:
  - Why Header & Footer Broke:
    Header.tsx and Footer.tsx use Avada CSS classes (.fusion-tb-header, .fusion-tb-footer).
    Those classes depend on parent ancestor classes (.wp-theme-Avada, .fusion-body, .avada-responsive).
    When previous rewrites discarded the wrapper div and Avada classes, the CSS rules
    for Header and Footer failed to match.
  - Why 1-to-1 Tag Translation Works (The Correct Solution):
    The browser does not care if DOM nodes come from HTML or React JSX.
    If we keep the exact DOM tree, the exact Avada classes, the wrapper classes
    (.wp-theme-Avada), and the exact inline style variables:
      - <div class="..."> -> <div className="...">
      - style="--awb-padding: 20px;" -> style={{ '--awb-padding': '20px' }}
      - <a href="/doors"> -> <Link href="/doors">
      - <img src="..." /> -> <Image src="..." ... />
    The browser applies the identical CSS selectors to the identical elements.
    It is mathematically guaranteed to render 100% identically!
