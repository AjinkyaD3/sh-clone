# Low-Level Technical Specification: Sitewide Mobile Responsiveness Engine

This document provides an exhaustive, low-level technical specification for implementing full mobile responsiveness across all 35 pages of the Secure House Next.js site.

---

## 1. Root-Cause Architecture & Specificity Cascade

### 1.1 The Specificity Cascade Problem
In the converted Next.js codebase, styling is governed by four competing layers:
1. **Scraped Inline HTML Styles**: Elements carry inline attributes generated by Avada (e.g., `style={{ width: '104% !important', '--awb-padding-top': '320px' }}`). Inline styles with `!important` have the highest possible specificity `(1, 0, 0, 0) + !important`.
2. **Page-Specific Compiled Avada Stylesheets**: Injected via `<link rel="stylesheet" href="/legacy-assets/uploads/fusion-styles/[hash].min.css">`. These contain thousands of minified rules using high-specificity selector chains (e.g., `body.fusion-body .fusion-builder-row-X .fusion-layout-column { ... }`).
3. **Global Extracted Styles**: [`app/theme-globals.css`](file:///c:/Users/AJINKYA/OneDrive/Desktop/SH%20NEXT%20JS/secure-house-nextjs/app/theme-globals.css) and [`app/globals.css`](file:///c:/Users/AJINKYA/OneDrive/Desktop/SH%20NEXT%20JS/secure-house-nextjs/app/globals.css).
4. **Layout Head Overrides**: Injected via inline `<style>` in [`app/layout.tsx`](file:///c:/Users/AJINKYA/OneDrive/Desktop/SH%20NEXT%20JS/secure-house-nextjs/app/layout.tsx).

### 1.2 Why Sub-Pages Fail on Mobile
In WordPress, Avada solved viewport scaling via client-side JavaScript (`fusion-responsive-typography.js`, `fusion-column.js`, `jquery.isotope.js`):
* **Typography Calculation**: The script read `--fontSize: 50` and dynamically updated `font-size` on window resize. In Next.js, without this JS, headings render at their desktop static values (50px, 45px, 36px), destroying mobile readability.
* **Inline 104% Width Trap**: Scraped rows use `width: 104% !important; margin-left: calc(-4% / 2)`. On desktop, this provides margin bleed for gutters. On mobile viewports (<640px), this pushes content outside the viewport by 2% on each side, causing horizontal page wobble.
* **Inline Desktop Padding Traps**: Elements have inline padding (e.g. `padding: 0 200px;` or `padding-top: 320px;`). On a 390px mobile device, `200px + 200px = 400px` of horizontal padding, leaving negative space for content.
* **Multi-Column Width Inheritance**: Columns carry inline CSS variables like `--awb-width-large: 50%`, `--awb-width-small: 100%`. However, because Avada's flexbox column rules in CSS were stripped or lack runtime evaluation, the `50%` desktop width persists, squeezing cards into narrow, broken vertical columns.

## 2. Breakpoint Architecture & System Tokens

The responsive engine operates across 4 distinct breakpoints:

| Breakpoint Name | Media Query | Target Devices | Behavior |
| :--- | :--- | :--- | :--- |
| **Small Mobile** | `@media only screen and (max-width: 480px)` | iPhone SE, Galaxy A-series (320px – 480px) | Single column, tight 16px gutters, compact headings |
| **Standard Mobile** | `@media only screen and (max-width: 767px)` | iPhone 12/13/14/15, Pixel, Galaxy S (481px – 767px) | Single column, 20px gutters, full-width cards |
| **Tablet Portrait** | `@media only screen and (min-width: 768px) and (max-width: 1024px)` | iPad Mini, iPad Air, Galaxy Tab (768px – 1024px) | 2-column grids, adjusted header padding, tablet off-canvas |
| **Desktop Baseline** | `@media only screen and (min-width: 1025px)` | Desktops, Laptops (1025px+) | Unaltered desktop layout (preserves existing parity) |

```css

  body {
    overflow-x: hidden !important;

    position: relative;
    -webkit-text-size-adjust: 100%;

  #content {
    width: 100% !important;
    max-width: 100vw !important;
    overflow-x: hidden !important;
  }

  /* Neutralize 104% width and negative gutter margins */
  .fusion-builder-row,
  .fusion-builder-row-inner,
  .fusion-row {
    width: 100% !important;
    max-width: 100% !important;
    margin-left: 0 !important;
    margin-right: 0 !important;
    padding-left: 0 !important;
    padding-right: 0 !important;

  .fusion-fullwidth {
    padding-left: 16px !important;

    box-sizing: border-box !important;
  }
}
```

## 4. Per-Archetype Audit & Specification Matrix

All 35 pages fall into 5 structural archetypes:

### Archetype 1: Homepage (`/`)
* **Key Components**: Hero Slider (`HeroSlider.tsx`), Trust Logo Marquee, Post Cards (`.post-card-item`), YouTube Video embed, Testimonials.
* **Low-Level Mobile Target**:
  - `HeroSlider-module__heading`: clamped to 28px–34px.
  - Video columns: stacked 100%.
  - Category preview cards: stacked 100% with gradient scrim.

### Archetype 2: Category Hubs (`/doors`, `/windows`, `/garage-doors`, `/door-styles`, `/products`)
* **Key Components**: Category Hero, `.fusion-column-liftup-border` child cards, Intro Text.
* **Low-Level Mobile Target**:
  - Cards stack 1 per row on mobile (`max-width: 640px`) and 2 per row on tablet (`641px–1024px`).
  - Scrim gradient behind titles forced visible via `--awb-inner-bg-image`.

### Archetype 3: Product Detail Pages (20 Pages)
* **Key Components**: `/doors/bullet-proof-doors`, `/doors/fire-resistant-doors`, `/windows/high-security-steel-windows`, etc.
* **Low-Level Mobile Target**:
  - Parallax banner images: `background-attachment: scroll !important` on iOS/Android (iOS disables `background-attachment: fixed` or causes rendering bugs).
  - FAQ Accordions: full-width, touch targets >= 48px.
  - Galleries: 2 columns with `GalleryLoadMore.tsx` reveal.

### Archetype 4: Filterable Listings (`/projects`, `/blog`)
* **Key Components**: Filter tabs (`.fusion-filters`), project grid cards.
* **Low-Level Mobile Target**:
  - `.fusion-filters`: wrap horizontally with `flex-wrap: wrap; justify-content: center; gap: 8px;`.
  - Filter buttons: `padding: 8px 16px; border-radius: 20px; font-size: 13px;`.

### Archetype 5: Inquiry & Static Pages (`/contact-us`, `/about-us`, `/trade`, `/security-levels`)
* **Key Components**: Contact form, address columns, phone triggers.
* **Low-Level Mobile Target**:
  - Full-width inputs with 16px font size to prevent iOS viewport auto-zoom.
  - Click-to-call phone links (`tel:02078594207`) explicitly styled as touch targets.

## 5. File Delivery Architecture

To maintain documentation integrity and clean separation of concerns:
1. **Target Stylesheet**: Create [`app/styles/mobile-responsive.css`](file:///c:/Users/AJINKYA/OneDrive/Desktop/SH%20NEXT%20JS/secure-house-nextjs/app/styles/mobile-responsive.css).
2. **Mount Point**: Import into [`app/layout.tsx`](file:///c:/Users/AJINKYA/OneDrive/Desktop/SH%20NEXT%20JS/secure-house-nextjs/app/layout.tsx):
   ```tsx
   import "./styles/mobile-responsive.css";
   ```
3. **Zero JSX Regressions**: By isolating mobile styling rules in this cascading stylesheet, zero individual `page.tsx` files are modified, completely eliminating the risk of broken imports or React rendering bugs.
